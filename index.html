04About Me

ariel@feider:~$ cat about.txt

Security has been part of my life since I was about 13 years old. My father and I got into it together: setting up machines, breaking things, figuring out how they worked and how to protect them. What started as a shared hobby at home became a real passion, and it's the reason I started my Computer Science degree at just 14.

That same year, at 14, I also started competing in Capture The Flag (CTF) challenges, and I've done a lot of them since on platforms like Hack The Box, TryHackMe and CTF 24/7. CTFs are where I sharpened my practical skills in exploitation, reverse engineering, cryptography and web security.

Today I'm a final-year CS student and a developer who focuses on security. I'm drawn to offensive security and secure system exploitation, and I balance that with the defensive side: understanding attacks well enough to stop them. I have hands-on experience in penetration testing, vulnerability research, reverse engineering and secure programming. I also work with AI: most of my projects include parts that are run by AI agents.

I'm motivated by strengthening the IDF's digital and defensive capabilities. I thrive on complex, high-stakes technical challenges and aim to contribute to that mission with precision, responsibility and a strong technical foundation.

05Projects

Ransomware Simulation & Analysis

COMPLETED

I designed and built a ransomware simulation from scratch and ran it only inside an isolated, controlled virtual-machine environment. The goal was to understand ransomware from the attacker's side, step by step, so I could understand how to detect it, contain it and recover from it.

// WHAT I DID
  • Set up a sandboxed lab of virtual machines with no access to real networks or real data, so the simulation could run safely and be reset at any time.
  • Implemented the core behavior: finding target files, encrypting them, and managing the encryption keys, which gave me hands-on experience with how symmetric and asymmetric encryption work together in practice.
  • Watched the simulation run with security tools to see the traces it leaves behind: file activity, process behavior and system changes that defenders can spot.
  • Documented defensive mitigations based on what I observed, including backups, early detection signals and ways to limit how far an infection can spread.

Home Penetration Testing Lab

ONGOING

I built and maintain a personal penetration testing lab where I practice the full process of an attack, from reconnaissance to exploitation, against machines that are made to be vulnerable. It's my space to learn new techniques, test tools and sharpen my skills on both the offensive and defensive side.

// WHAT I DID
  • Built a virtual network with a Kali Linux attack machine and several intentionally vulnerable Linux and Windows targets.
  • Worked through full attack scenarios following the stages of the Cyber Kill Chain: reconnaissance, weaponization, delivery, exploitation, installation, command & control and actions on objectives, using Kali's standard toolset.
  • Mapped each stage to where a defender could detect or break the chain, practicing offensive and defensive thinking side by side.
  • Captured and analyzed network traffic in Wireshark to see what each attack looks like on the wire and how a defender could detect it.
  • Wrote small Bash and PowerShell scripts to automate repetitive recon and enumeration tasks on Linux and Windows.
  • Used AI agents to help automate parts of the workflow, such as organizing scan results and summarizing findings into short reports.
